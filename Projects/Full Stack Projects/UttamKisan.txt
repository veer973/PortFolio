# UttamKissan

## Project Type

Smart Agriculture Marketplace & Autonomous Rover Rental Platform

## One-Line Description

A full-stack smart agriculture platform connecting farmers, agricultural retailers, laborers, and autonomous agricultural rovers through a unified digital ecosystem.

## Project Overview

UttamKissan combines three major systems into one platform:

**Agricultural Marketplace + Labor Platform + Autonomous Rover Rental System**

The platform enables farmers to purchase agricultural equipment and products, sell agricultural produce, find agricultural workers, rent autonomous agricultural rovers, schedule field operations, make online payments, and monitor rover operations.

The platform serves four major user roles:

* Farmer
* Agricultural Retailer
* Agricultural Laborer
* Administrator

## Problem

Small and medium-scale farmers often deal with disconnected agricultural services.

Common challenges include:

* Difficulty accessing agricultural equipment
* Difficulty finding agricultural labor
* High cost of purchasing machinery
* Difficulty selling agricultural produce
* Limited access to agricultural automation technology

UttamKissan brings these services into a single platform instead of requiring farmers to independently arrange equipment, workers, machinery, payments, and field operations.

# Autonomous Rover Rental System

## Main Differentiator

The autonomous rover rental system is the feature that differentiates UttamKissan from a conventional marketplace application.

Instead of simply listing an agricultural rover as a product, the platform treats the rover as a service that can be scheduled and rented for field operations.

A farmer selects:

Field
↓
Operation
↓
Attachment
↓
Date/Time
↓
Rental Duration
↓
Payment
↓
Rental Confirmation

Example:

Field: 2 acres
Operation: Seeding
Attachment: Seed Drill
Date: 20 August
Time: 08:00–11:00
Rental Duration: 3 hours

The platform then creates and manages the rover rental.

## Rover Operations

The rover can be used for agricultural operations such as:

* Tilling
* Land leveling
* Seeding

Compatible attachments include:

* Tiller
* Leveler

The platform connects the selected operation with the appropriate attachment and rover.

# Serpentine Navigation Visualization

The rover uses a serpentine field-navigation pattern for agricultural operations.

Conceptually:

START
→ → → → →
← ← ← ← ←
→ → → → →
← ← ← ← ←
END

The web platform does not need to implement low-level motor control. Instead, it manages the agricultural mission and visualizes the rover's operational state.

Example mission:

Operation: SEEDING
Field: Field #102
Attachment: Seed Drill
Path: SERPENTINE
Status: RUNNING

# Rental Scheduling and Availability

The platform includes business-rule validation for rover reservations.

A rover cannot be booked by two farmers for overlapping time periods.

Example:

Rover RV01
09:00–12:00 → Farmer A
12:30–15:30 → Farmer B

This is valid.

But:

09:00–12:00 → Farmer A
11:00–14:00 → Farmer B

must be rejected because the reservations overlap.

The backend checks existing reservations before confirming a rental.

This demonstrates real scheduling and business-logic validation beyond simple CRUD operations.

Role permissions are enforced on the backend.

Example:

Farmer → Create rover rental
Retailer → Create equipment listing
Laborer → Apply for agricultural jobs

Frontend UI restrictions are not treated as security. Backend authorization verifies whether the authenticated user is allowed to access or modify a resource.

# Error Handling

The backend should use centralized error handling with appropriate HTTP responses:

401 Unauthorized → Invalid authentication
403 Forbidden → Insufficient permissions
404 Not Found → Resource does not exist
400 Bad Request → Invalid request

Raw database errors should not be exposed directly to the frontend.

# Security

Security features include:

* JWT authentication
* bcrypt password hashing
* Role-based authorization
* Protected APIs
* Server-side authorization
* Input validation
* Secure payment verification
* Restricted resource access
* Audit logging
* Environment variables for secrets

Resource ownership must also be verified server-side.

For example, a farmer must not be able to modify another farmer's rental simply by knowing its ID.
